# kzp-lab_1-5

Лабораторна робота № 1 з курсу «Кросплатформні засоби програмування». Варіант 14 — **Готель**.

## Призначення

Консольна програма читає записи про проживання гостей із CSV-файлу, перевіряє їх і обчислює:

1. кількість коректних записів;
2. сумарну кількість ночей;
3. загальний виторг (ночі × ціна за ніч);
4. найдовше проживання.

Хибні рядки пропускаються з повідомленням про номер рядка та причину. Звіт виводиться в консоль і записується у файл.

## Формат входу

Файл `data/input.csv`, UTF-8, один запис у рядку, роздільник `;`, десяткові числа з крапкою:

```
room;guest;nights;nightlyRate;category
```

| Поле | Тип | Обмеження |
|------|-----|-----------|
| room | int | більше 0 |
| guest | String | не порожнє |
| nights | int | більше 0 |
| nightlyRate | double | не менше 0 |
| category | String | не порожнє |

Приклад: `101;Іваненко Петро;3;1200.50;Standard`

## Структура програми

```
src/main/java/ua/lpnu/kzp/
├── Main.java        — аргументи командного рядка, читання файлу, звіт
├── Booking.java         — абстрактний (sealed) базовий тип: спільні поля, валідація, fromCsv, equals/hashCode
├── StandardBooking.java — стандартне проживання: ночі × тариф
├── PremiumBooking.java  — преміальне проживання: знижка 10% після 10 ночей
├── RoomKind.java        — enum виду номера (ECONOMY, STANDARD, LUX)
├── NightsRate.java      — record «ночі + тариф», обчислення вартості
├── BookingQueries.java  — запити Stream API до списку бронювань
├── Repository.java      — параметризоване сховище Repository<T>
├── CsvColumn.java       — анотація назви CSV-стовпця (RUNTIME, FIELD)
├── CsvExporter.java     — універсальний рефлексивний CSV-експортер
├── CsvParser.java       — документний CSV-парсер (лапки, коми, переноси рядків)
├── BookingRecord.java   — плоский запис із датами для CSV (поля з @CsvColumn)
└── DataStorageException.java — власний checked-виняток із cause
```

Потік даних: CSV-рядок → `Booking.fromCsv` → `List<Booking>` (підтипи `StandardBooking`/`PremiumBooking`) → показники → звіт.

### Ієрархія Booking

`Booking` — абстрактний `sealed`-клас, який дозволяє лише `StandardBooking` і `PremiumBooking`. Він містить спільні `private final`-поля, конструктор з інваріантами, фабрику `fromCsv(String)`, геттери, `equals`/`hashCode` (за точним типом і всіма полями) та `toString` з `Locale.ROOT`. Абстрактний метод `getRevenue()` реалізують підтипи:

- `StandardBooking` — ночі × тариф;
- `PremiumBooking` — те саме, але зі знижкою 10%, якщо ночей строго більше 10.

`Main` працює зі `List<Booking>` і викликає `getRevenue()` без перевірки типу об'єкта — це поліморфізм.

### RoomKind

`enum` з трьома значеннями: `ECONOMY`, `STANDARD`, `LUX`. Визначається за категорією з CSV без урахування регістру (`fromCategory`); невідома категорія вважається `STANDARD`. `LUX` дає `PremiumBooking`, решта — `StandardBooking`.

### BookingQueries

Запити Stream API до `List<Booking>` без ручних циклів і перевірки підтипу; вхідний список не змінюється:

| Запит | Метод | Операції | Результат |
|-------|-------|----------|-----------|
| відбір | `longStays(list, minNights)` | `filter` | `List<Booking>` |
| перетворення | `roomNumbers(list)` | `map` | `List<Integer>` |
| групування | `countByRate(list)` | `groupingBy` + `counting` | `Map<Double, Long>` (за зростанням тарифу) |
| статистика | `nightsStatistics(list)` | `summarizingInt` | `IntSummaryStatistics` |
| топ-N | `topLongest(list, n)` | `sorted` (ночі спадаючи, потім номер) + `limit` | `List<Booking>` |
| пошук | `findByRoom(list, room)` | `filter` + `findFirst` | `Optional<Booking>` |

Також `longestStay` (`max`, `Optional`) і `totalRevenue` (`map` + `reduce`) — на них будується звіт у `Main`.

Фільтр «активне на дату» з таблиці варіанта замінено на «проживання від N ночей», бо вхідний CSV (незмінний за вимогою) не містить дат.

### Сховище, CSV-експорт та імпорт

- `Repository<T>` — `add`, `all()` (незмінний знімок), `find(Predicate<? super T>)`.
- `@CsvColumn("назва")` над полем задає заголовок стовпця.
- `CsvExporter` читає рефлексією поля з `@CsvColumn` будь-якого класу (без прив'язки до домену). Порядок стовпців — за іменем поля; значення екрануються (кома, лапка, перенос рядка → лапки, лапки подвоюються); запис у UTF-8 з перезаписом файлу.
- `CsvParser.parseDocument` читає весь документ і повертає записи, а не фізичні рядки.
- `BookingRecord` — запис із датами: `номер, гість, заїзд, виїзд, тариф` (у файлі порядок за іменами полів: `заїзд,виїзд,гість,тариф,номер`).
- Помилки (формат, значення, файл, рефлексія) — `DataStorageException` із `cause`.

Приклад (`data/records.csv`):

```
заїзд,виїзд,гість,тариф,номер
2026-10-01,2026-10-04,Іваненко Петро,1200.5,101
2026-10-02,2026-10-09,"Коваль, Олена",2000.0,102
2026-10-05,2026-10-07,"Бондар ""Макс"" Максим",850.0,103
```

### NightsRate

`record NightsRate(int nights, double nightlyRate)` — незмінне значення з перевіркою в компактному конструкторі та методом `revenue()` (ночі × тариф).

### Правила валідації

- `guest`, `category` — не порожні (пробіли по краях обрізаються);
- `room` — ціле, більше 0;
- `nights` — ціле, більше 0;
- `nightlyRate` — скінченне число, не менше 0.

### Відмінності від попередньої роботи

У ЛР2 `Booking` був одним конкретним класом. У ЛР3 він став абстрактним базовим типом, з'явилися підтипи `StandardBooking` і `PremiumBooking`, enum `RoomKind` та узгоджені `equals`/`hashCode`. Формат CSV, повідомлення про помилки та звіт на `data/input.csv` не змінилися.

## Запуск

Потрібна Java 21. Maven встановлювати не потрібно — використовується Maven Wrapper.

```
./mvnw verify          # збірка і тести (Windows: mvnw.cmd verify)
./mvnw package         # jar у target/
java -jar target/lab01-5.0.1.jar [--input <файл>] [--output <файл>]
```

| Аргумент | Опис |
|----------|------|
| `--input` | вхідний CSV (за замовчуванням `data/input.csv`) |
| `--output` | файл звіту (за замовчуванням `output/report.txt`) |
| `--records` | CSV із датами для імпорту (заголовок + записи) |
| `--export` | куди експортувати імпортовані записи (за замовчуванням `output/records.csv`) |
| `--help` | довідка |
| `--version` | версія програми |
