# Звіт до лабораторної роботи № 1

## 1. Тема, номер і варіант

Розгортання Java-проєкту та базова обробка даних. Лабораторна робота № 1, варіант 14 — «Готель». Операційна система: Windows.

## 2. Мета роботи

Пройти шлях від створення репозиторію й налаштування інфраструктури до консольної програми, яку можна відтворено зібрати й запустити на Windows, macOS та Ubuntu. Досягнуто: створено Maven-проєкт із Maven Wrapper, програму читання й перевірки записів, обчислення показників, звіт у консоль і файл, тести JUnit 5 та CI на трьох ОС.

## 3. Постановка задачі

Формат запису: `room:int; guest:String; nights:int; nightlyRate:double; category:String`.

Показники:
1. кількість коректних записів;
2. сумарна кількість ночей;
3. загальний виторг;
4. найдовше проживання.

## 4. Структура програми

```
pom.xml
mvnw, mvnw.cmd, .mvn/
data/input.csv
src/main/java/ua/lpnu/kzp/Main.java
src/test/java/ua/lpnu/kzp/MainTest.java
.github/workflows/ci.yml
```

Потік даних: `main` розбирає аргументи → `run` читає файл (`Path`, UTF-8) → `buildReport` перевіряє рядки, накопичує показники й формує текст → звіт друкується в консоль і записується у файл.

## 5. Інфраструктура

- Maven (`ua.lpnu.kzp:lab01:1.0.0`), Java 21, UTF-8; Maven Wrapper (`mvnw`, `mvnw.cmd`).
- Залежність: JUnit Jupiter 5.12.2 (scope `test`), плагін surefire 3.5.3.
- Пакування: `maven-jar-plugin` із `mainClass` `ua.lpnu.kzp.Main`.
- CI: GitHub Actions (`.github/workflows/ci.yml`) запускає `./mvnw -B verify` на ubuntu-latest, windows-latest і macos-latest.
- Виконано: статичний аналізатор (SpotBugs), публікація артефакта, версія в `--version` і Git-тег.

## 11. Відповіді на контрольні питання

1. `pom.xml` описує Maven-проєкт: координати (groupId, artifactId, version), версію Java, кодування, залежності й плагіни.
2. `test` компілює й запускає тести; `verify` додатково виконує перевірки якості (наприклад, статичний аналіз); `package` після цього створює jar у `target/`. Кожна наступна фаза виконує попередні.
3. Maven Wrapper дозволяє збирати проєкт без глобально встановленого Maven і з однаковою його версією на всіх комп'ютерах та в CI.
4. `main` — точка входу: JVM починає виконання програми з цього методу.
5. Примітивний тип (int, double) зберігає саме значення, не є об'єктом і не може бути `null`. `String` — клас, змінна містить посилання на об'єкт і має методи.
6. Бо цілочислове ділення відкидає дробову частину: 7 / 2 = 3. Приведення до `double` дає 3.5.
7. Буде кинуто `NumberFormatException`.
8. Тоді користувач не знає, що частину даних не враховано, і результат може бути хибним. Потрібно повідомляти номер рядка та причину.
9. Із `-1` порожнє останнє поле зберігається як порожній рядок; без нього кінцеві порожні поля відкидаються.
10. `Path.of` сам підставляє роздільник відповідної ОС, а зашитий `\\` працює лише на Windows.
11. Щоб кодування не залежало від налаштувань ОС: інакше кирилиця може читатися неправильно.
12. `%n` дає роздільник рядків поточної платформи (`\r\n` у Windows, `\n` в Unix), а `\n` — завжди лише символ переведення рядка.
13. Кількість полів, порожній рядок, непорожні `guest` і `category`, числовий формат `room`, `nights`, `nightlyRate`, `room` і `nights` більше нуля, `nightlyRate` не від'ємна, наявність хоча б одного коректного запису.
14. Тест із відомими вхідними даними та очікуваним значенням, де сума не ділиться націло на кількість (наприклад, 7 і 2 → 3.5), порівняння дробових чисел із допуском. Якщо в середньому використати цілочислове ділення, такий тест упаде.
15. Статичний аналізатор шукає потенційні помилки в коді або байт-коді без запуску програми.
16. GitHub Actions автоматично запускає збірку, тести та перевірки на серверах GitHub, у моєму випадку на трьох ОС для кожної зміни.
17. Опис дефекту, кроки відтворення, очікуваний і фактичний результат, середовище (ОС, версія Java).
18. Які інструменти ШІ використано, для чого, які поради прийнято, які помилки виправлено, і підтвердження, що я розумію весь поданий код.
19. DevOps налаштовує інфраструктуру: збірку, CI, пакування. Валідатор перевіряє коректність програми: крайові випадки та тести.
20. Рядок `revenue += nights * rate;` — тут цілочислове `nights` множиться на `double`, тому результат обчислюється в `double`, а не відкидає дробову частину.
